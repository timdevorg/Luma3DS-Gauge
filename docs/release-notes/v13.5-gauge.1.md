# Luma3DS-Gauge v13.5-gauge.1

The first release of Luma3DS-Gauge: Luma3DS v13.5 with a **Battery Manager** in the Rosalina menu, for consoles
with an **aftermarket battery**.

With a replacement cell the console's fuel gauge is wrong. The MCU applies the stock battery's discharge curve,
so the power LED turns red and starts blinking while the console can still run for hours (at the stock red point
about a third of the charge was really left on the test console). The Battery Manager learns how your battery really discharges and corrects the LED and
the HOME Menu battery icon.

## What's included

- **`boot.firm`**: a complete Luma3DS v13.5 build with the Battery Manager. Nothing else changes.
- **Power LED correction:** blue above 10 %, solid red at 10 % and below, blinking red at 3 % and below, judged
  from the *corrected* battery level. Both thresholds can be changed. Within one discharge the LED only ever gets
  worse (blue → red → blinking), so it doesn't flicker. While charging it is always blue. Off by default, and you
  switch it on once you have a curve.
- **Sleep LED:** with the lid closed the LED shows dim blue (default), bright blue or the console's stock
  behaviour. Solid red stays solid red, and the genuine low-battery blink is left to the console.
- **HOME Menu battery bars:** the battery icon follows the corrected level (4 bars from 70 %, 3 bars from 40 %, both
  adjustable; one red bar and a blinking bar at the same moments as the LED). While charging the icon holds the
  level from before. HOME Menu's "battery running low" notification follows the corrected level too.
- **Curve learning:** record full discharges on the console and build a curve from them. A graph compares it with
  the stock curve, and the previous curve is kept as a backup that you can restore.
- **Menus:** a home screen with a live summary and a "Next:" hint, one Settings screen, Learning (recording,
  sessions, build, graph), a Setup guide, and Advanced (Diagnostics, LED test, Blue LED type, Restore previous
  curve, Limits and about).
- **Rosalina footer:** shows the stock and corrected level, e.g. `3.6%→29.9%`.
- **Time remaining:** an estimate on the Battery Manager home screen ("Time left"), from the recent drain at the
  current load. It appears after about 10 minutes on battery and starts over after charging or sleep. Not shown in
  the Rosalina footer. Not yet tested on hardware.

## Requirements

- A **New 3DS, New 3DS XL or New 2DS XL** with **Luma3DS already installed** (boot9strap).
- **Tested on one console only:** a New 3DS XL with an iFixit replacement battery. The New 3DS and New 2DS XL have
  not been tested.
- The Sleep LED and HOME Menu bars patches only match the New 3DS ptm system module (`0004013020002202`) they were
  made for. If the code doesn't match, they switch themselves off and stay stock (Advanced → Diagnostics shows
  why). Old 3DS / 2DS models use a different ptm: LED correction may work there, but the Sleep LED and bars won't.

## Install

1. Put the SD card in your computer (or use ftpd).
2. **Back up** the current `/boot.firm` from the root of the SD card, e.g. as `boot.firm.orig` on your computer.
3. Optional, recommended: copy that original `boot.firm` to `/luma/payloads/x_recovery.firm`.
4. Copy the `boot.firm` from this release to the root of the SD card, replacing the old one.
5. Boot the console. Open Rosalina with **L + Down + Select**. You should see **Battery Manager...**.

## Revert

Put your backed-up `boot.firm` back in the root of the SD card. That's all: nothing was written to NAND or the MCU
firmware, and the ptm changes live in RAM only. You can delete `/luma/battery/` too if you like.

## Recovery

If the console doesn't boot normally with this `boot.firm` and you created `/luma/payloads/x_recovery.firm`,
**hold X while powering on**. Luma's chainloader then starts your original Luma. Otherwise, put the SD card in a
computer and restore the old `boot.firm`.

## How it works

- **The curve.** The stock gauge reports a % that is right for the original battery, not for yours. During a
  recording the Battery Manager logs the stock % and the voltage every 10 s, from full until the console switches
  itself off. For each stock % it then knows how much of the runtime was still left, which is the *real* %.
  Several sessions are averaged into a curve (`curve.bin`) that maps stock % → real %. For the last few percent,
  where the stock gauge stops moving, it uses the battery voltage instead.
- **Power LED.** About once a second it looks up the corrected % and picks blue, solid red or blinking red from
  your thresholds. Writing the LED mode to the MCU is its only MCU write. If the system takes the LED back, the
  Battery Manager notices and sets it again. If that keeps failing, it hands the LED back to the console and shows
  an error.
- **Sleep LED.** When the lid closes, the system module ptm sends its own sleep and wake LED commands. The
  Battery Manager changes those two bytes in ptm's RAM so that they match the corrected level. While asleep
  nothing of ours runs, so the LED shows the level from when the lid was closed. The Sleep LED only applies
  while the Power LED is set to corrected.
- **HOME Menu bars.** ptm turns the gauge % into the HOME Menu battery level. The Battery Manager changes four
  bytes of that code in ptm's RAM so that the level comes from the corrected %. HOME Menu picks up a change within
  about 8 s. This works independently of the Power LED setting, but needs a curve.
- **Time remaining.** The home screen fits a line through the corrected % of the last 30 minutes and divides
  the % left by that drain rate, so it reflects the current load (brightness, Wi-Fi, game). It shows after about
  10 minutes on battery, starts over after charging or sleep, and is kept in RAM only. It is not shown in the
  footer.

Each ptm patch checks the surrounding code before every write and again after it. On any mismatch it switches
itself off for that boot.

Full details: [docs/battery-manager.md](https://github.com/timdevorg/Luma3DS-Gauge/blob/battery-manager/docs/battery-manager.md).

## First-time setup

The **Setup guide** (Rosalina → Battery Manager... → Setup guide) ticks off these steps as you go.

1. **Charge to 100 %.** Leave the charger on until the charge LED turns off, ideally 15–30 minutes longer, then unplug.
2. **Learning → Start recording.** To be usable, a recording must start at 95 % or more on the stock gauge. It
   has to run on the battery (it won't start on the charger).
3. **Play until the console switches itself off.** Use your usual brightness, 3D and Wi-Fi settings and turn
   power-saving mode off. **Don't close the lid and don't plug in the charger.** Either one spoils the session
   (sleep gap) or ends it.
4. **Learning → Build curve.** Usable sessions are listed and selected. A session that ended above 5 % (probably
   switched off by hand) is left unselected. Press X and confirm.
5. **Settings → Power LED: corrected.** After the first build the Battery Manager offers to do this for you.

One session is enough to start. Two or three give a better average, and the graph's band shows how much they
differ. In **Settings** you can also change the Sleep LED, turn the HOME Menu bars on or off, and change the
thresholds. Press B to save, or SELECT to undo.

## Files on the SD card

Everything is under `/luma/battery/`:

| File | What |
|---|---|
| `config.ini` | Your settings (Power LED, thresholds, Sleep LED, bars). Written only when you save a change, so missing = defaults. |
| `sessions/NNNN.csv` | One file per recording (`0001.csv`, `0002.csv`, ...): a sample every 10 s, plain text. |
| `curve.bin` | The current curve. |
| `curve.bak` | The previous curve, kept on every build. Advanced → Restore previous curve swaps the two. |
| `curve_select.ini` | Which sessions you selected for the curve. |
| `config.tmp`, `curve.tmp` | Short-lived temporary files used for safe saving. They normally disappear right away. |

Deleting `curve.bin` does nothing until the next boot: the curve is loaded into RAM once at boot (and after Build
curve / Restore previous curve) and stays in use. From the next boot on there is no curve, so the LED and bars are
back to stock (unless a leftover `curve.tmp` exists, which the loader uses instead). Deleting the whole folder resets everything.

## Known limits

- For the first ~5 s after power-on the LED is the console's own (it may blink red if the stock gauge thinks the
  battery is low). Rosalina isn't running yet.
- The LED can't follow the battery live during sleep. A level that drops while asleep shows when you open the lid.
- A charger plugged in (or unplugged) during sleep changes nothing until the lid opens.
- The Sleep LED and HOME Menu bars depend on the exact New 3DS ptm version (see Requirements).
- The HOME Menu bars refresh about every 8 s.
- Learning currently needs complete discharges (from ≥ 95 % to automatic power-off, no sleep). Passive learning
  from partial sessions is planned.
- Apps that read the gauge directly (e.g. homebrew) still see the stock %.
- The curve is learned from your own use. If your typical load is very different from what you recorded, it is
  less accurate.

## Safety

- **No MCU firmware changes and no NAND writes.** The fuel gauge chip is not reachable and not touched.
- Everything lives in `boot.firm` plus files under `/luma/battery/` on the SD card.
- There are only three kinds of hardware writes, each whitelisted and verified:
  1. MCU register `0x29`, the power LED mode byte (values 0–6 only).
  2. ptm's sleep / wake LED bytes in RAM.
  3. ptm's 4 battery-bar bytes in RAM.
- The ptm changes are RAM only and vanish at the next boot. A reboot also hands the LED back to the console.
- To revert, restore your original `boot.firm`.
